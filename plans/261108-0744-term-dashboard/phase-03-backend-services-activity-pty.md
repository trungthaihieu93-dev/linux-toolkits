# Phase 3: Backend services, activity stream and PTY

## Goal
Implement every backend capability behind the REST, SSE and WebSocket routes: guarded command execution with live activity, safe file writes, gsettings and Ghostty services, shell files, settings and the PTY terminal.

## Files to create (under `ubuntu/apps/term-dashboard/src/`)
- `exec/command-runner.ts`: `run(argv, { cwd?, env?, input?, timeoutMs? })` built on `execFile`/`spawn` with an argv array only (no `shell: true`). Emits `ActivityEvent`s (`started`, `output` per chunk with stream, `exited` with code and duration) to `ActivityBus`. `RecordingCommandRunner` for tests returns scripted results and records calls, mirroring `RecordingRunner` in `libs/core`.
- `exec/activity-bus.ts`: in-memory pub/sub with a history ring buffer capped at 500 commands and 2 MB, so a reconnecting client gets recent history. Every command is streamed; output beyond 64 KB per command is replaced by one `output` event stating the truncated byte count (for example the 186 KB Ghostty docs dump).
- `files/file-store.ts`: `read(id)` and `write(id, content, { check })` for an allowlist of ids, not paths: `bashrc`, `bash_profile`, `bash_aliases`, `profile`, `zshrc`, `zshenv`, `zprofile`, `ghostty`, `ghostty-legacy` (resolved against the target `HOME`/`XDG_CONFIG_HOME`). The backups directory is `0700` and backup files are `0600`, since rc files often export tokens. Write = optimistic concurrency on `mtimeMs` (409 when the file changed since it was read) → copy current file to `~/.local/state/term-dashboard/backups/<iso-ts>/<id>` → write a temp file in the same directory with the original mode → run the check (`bash -n <tmp>`, `zsh -n <tmp>`, or `ghostty +validate-config --config-file=<tmp>`) through `CommandRunner` → `rename`. Refuse symlinked targets outside `HOME` and resolve symlinks inside it to write the real file. `listBackups(id)`, `restore(id, backupTs)` (restore itself takes a backup first).
- `files/preview.ts`: unified diff (`diff` package) between current and candidate plus the check result, returned before any write.
- `gsettings/gsettings-service.ts`: uses only `gsettings`, never the `dconf` CLI. `dconf` ignores `GSETTINGS_BACKEND`, so in a sandboxed test it would read and write the real database. `inventory()` checks for `org.gnome.Ptyxis*` and `org.gnome.Terminal.*` schema XML in `$XDG_DATA_DIRS/glib-2.0/schemas`. `schemaView(schema, path?)` = metadata from the parsed XML (cached per run) + values from one `gsettings list-recursively SCHEMA[:PATH]` + defaults from one `GSETTINGS_BACKEND=memory gsettings list-recursively SCHEMA[:PATH]`, so a page load costs two processes per schema instead of five per key. `set(schema, path, key, gvariantText)` and `reset(...)` call `gsettings set`/`reset`. Profiles: Ptyxis `profile-uuids` + `org.gnome.Ptyxis.Profile:/org/gnome/Ptyxis/Profiles/<uuid>/`; GNOME Terminal `org.gnome.Terminal.ProfilesList` `list` + `org.gnome.Terminal.Legacy.Profile:/org/gnome/terminal/legacy/profiles:/:<uuid>/` (confirm these ids from the XML at implementation time; GNOME Terminal is not installed here). Create = new uuid (32 hex for Ptyxis, dashed for GNOME Terminal), set the label, append to the list. Duplicate = copy every non-default key. Delete (after UI confirmation, never the default profile) = remove from the list, then `gsettings reset-recursively PROFILE_SCHEMA:PATH`. Backup before the first write per run: `list-recursively` of the global schema, shortcuts and every profile, saved as JSON in the backups folder. Restore = for each saved schema/path, `reset-recursively` then `set` every saved key, and reset profiles whose uuid is not in the saved list, so profiles created after the backup do not linger.
- `ghostty/ghostty-service.ts`: `available()` (`ghostty --version`), `schema()` (cache `+show-config --default --docs` per version), `themes()`, `fonts()`, `files()` (parse both files), `effective()` (`+show-config`), `save(edits)`. Ghostty documents its load order: `config.ghostty` first, then `config`, so `config` wins on a conflict. Rule: edit a key in the file that already sets it; new keys go to `config` when it exists, else `config.ghostty`; when both files set the key, edit the winning file and show a conflict notice. `config-file` includes are parsed read-only and listed; after each save, compare the edited keys with `+show-config` and warn when an include or the other file still overrides them. Repeatable keys with defaults (`keybind`, `palette`) support Ghostty's clear form (`keybind = clear`) so a user can remove defaults deliberately. Writes go through FileStore with the ghostty check.
- `shell/shell-service.ts`: per shell, read files, return `ShellFileView` (content + parsed block + outside summary + detected oh-my-zsh), `previewConfig(model)` and `saveConfig(model)` (re-render the block via term-config, FileStore with syntax check), `previewRaw(content)` and `saveRaw(content)`.
- `settings/settings-store.ts`: `~/.config/term-dashboard/settings.json` `{ theme: 'dark' | 'light', port, terminalShell? }`, validated on read, defaults when missing or invalid, atomic write.
- `pty/pty-session.ts`: spawn `setpriv --pdeathsig HUP -- script -qfec 'exec "$TD_SHELL" -il' /dev/null` with `TD_SHELL` in env, `TERM=xterm-256color`, `cwd=HOME`, `detached: true`. `--pdeathsig` sends `script` SIGHUP if `td` dies without running cleanups; `script` puts the shell in its own session (sid = shell pid). Initial size: wait for the child's tty (`/proc/<pid>/task/*/children` → child → `readlink /proc/<child>/fd/0`), then `stty -F <tty> cols C rows R`; resize repeats the stty call (kernel sends SIGWINCH). Data in/out as binary frames. On WS close, `td` exit (SIGINT/SIGTERM/SIGHUP) or child exit: SIGHUP to every process in the shell's session (`pkill -HUP -s <sid>`, which covers background jobs), then SIGKILL to the session and to `script` after 2 s. Max 4 concurrent sessions. WS messages over 64 KB close the socket; the upgrade handler is wrapped in try/catch and errors close the socket with code 1011.
- `server/routes/*.ts`: `settings`, `inventory`, `gsettings` (`/api/terminals/:kind/...`), `ghostty`, `shells/:shell`, `backups`, `activity` (SSE-formatted stream read via `fetch` with the bearer header; history replay, then live events; heartbeat every 15 s), `pty` (WS).
- Every route validates path and body identifiers with term-config's `validate.ts` before use; invalid input returns 400.
- Specs next to each module.

## Tasks & steps
1. CommandRunner + ActivityBus + SSE route, with a spec asserting event order for a successful and a failing command.
2. FileStore + preview with specs on a temp `HOME`: allowlist rejection, symlink escape rejection, 409 on mtime change, failed check leaves the original untouched and the temp file removed, backup then restore round-trip, mode preserved.
3. GSettingsService against `RecordingCommandRunner` with the phase 2 fixtures (asserting that no `dconf` argv is ever recorded), plus one integration spec that runs real `gsettings` with `GSETTINGS_BACKEND=keyfile` and a temp `XDG_CONFIG_HOME`, skipped when the Ptyxis schema is not installed: create, duplicate and delete a profile, back up, change keys, restore, and compare `list-recursively` with the original.
4. GhosttyService specs with fixtures, including a conflict across both files and an include that overrides an edited key; an integration spec using real `ghostty +validate-config` is skipped when `ghostty` is absent.
5. ShellService and SettingsStore specs on a temp `HOME`.
6. PtySession spec: spawn with `TD_SHELL=/bin/sh`, write `echo $((6*7))\n`, expect `42`; resize to 132x43 and read `stty size`; start `sleep 300 &`; close and assert no process with that session id remains (`pgrep -s <sid>` exits 1). A second spec runs `td` as a child, sends it SIGHUP and asserts the same. A third spec opens a real WebSocket to the running app and checks that a foreign `Origin` is rejected and the token subprotocol is accepted.
7. Wire routes into `app.ts`; register PTY cleanup on SIGINT/SIGTERM.

## Verification
- `bun --bun nx test term-dashboard` passes; integration specs report as skipped, not passed, where binaries are missing.
- Manual run in a sandbox: `HOME=$(mktemp -d) XDG_CONFIG_HOME=$HOME/.config GSETTINGS_BACKEND=keyfile td --no-open --port 0`, then use the API to save a zsh alias and a Ptyxis setting and confirm that only the sandbox changed: `sha256sum ~/.zshrc` and a read-only `dconf dump /org/gnome/Ptyxis/`, both taken in the real environment before and after, are identical.
- After `td` exits (by Ctrl-C and by closing its terminal), `pgrep -fu $USER 'script -qfec'` finds nothing and no shell started by td remains.
