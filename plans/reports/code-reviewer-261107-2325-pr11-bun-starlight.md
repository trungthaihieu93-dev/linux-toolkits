## SHOULD-FIX

### S1. The "Edit page" link on all 13 generated toolchain pages returns 404
- `website/astro.config.mjs:18` (`editLink.baseUrl`) and `website/scripts/render-toolchains.ts:278-285` (frontmatter)
- Failure: the built `ubuntu/toolchains/go/index.html` links to `.../edit/main/website/src/content/docs/ubuntu/toolchains/go.md`. That file is gitignored (`website/.gitignore`), so every generated page sends readers to a GitHub 404. This contradicts the page's own "do not edit" note.
- Fix: emit `editUrl: false` in the generated frontmatter, or point it at the catalog source, e.g. `editUrl: https://github.com/.../edit/main/ubuntu/libs/toolchains/src/toolchains/<id>.ts`. Add a renderer test for it.

### S2. Some copyable install commands have no `--dry-run`, which the brief forbids (needs a maintainer decision)
- `website/src/components/TerminalHero.astro:9`: the hero copy button copies `npx linux-toolchain`.
- `website/src/content/docs/ubuntu/quick-start.mdx:149-162`: step 3 has `npx linux-toolchain` / `bunx linux-toolchain`, titled "Terminal (installs)".
- `website/src/content/docs/ubuntu/usage.mdx:113`: inline `npx linux-toolchain --only go -y`. This installs with **no prompt at all**. A caution aside frames it, but it is still a copyable command.
- The brief says "any example with an install effect must carry --dry-run", and AGENTS.md (new Docs site section) says "install examples carry `--dry-run`". The interactive commands always end in a `Proceed?` review on a TTY. The `--only go -y` example has no gate at all.
- Fix: at minimum, rewrite usage.mdx:113 in prose ("adding `-y` to an id selection installs with no questions") or add `--dry-run` to it. For the hero and quick-start step 3, either get explicit sign-off that interactive launch commands are exempt and say so in AGENTS.md, or change the hero to `npx linux-toolchain --dry-run`.

### S3. The preview-comment upsert can pick up or edit someone else's comment
- `.github/workflows/docs.yml:143-144`
- Failure: the jq filter matches the first comment by **any** author whose body starts with `<!-- docs-preview -->`. On a public repo anyone can post such a comment. If it is the oldest match (for example, posted before the first deploy finishes), `gh api -X PATCH` gets 403 and `set -e` fails the deploy job. Every later push to that PR then goes red.
- Fix: `--jq ".[] | select(.user.login == \"github-actions[bot]\" and (.body | startswith(\"$marker\"))) | .id"`.

### S4. `lastUpdated: true` with a shallow checkout shows the same date on every page
- `website/astro.config.mjs:19` together with `.github/workflows/docs.yml:38` (`actions/checkout@v7`, default `fetch-depth: 1`)
- Failure: Starlight runs `git log` per file. In a depth-1 clone, every tracked page reports the HEAD commit time. So every hand-written page on production says "Last updated: <today's merge>", which is misleading.
- Fix: add `with: { fetch-depth: 0 }` to the docs build checkout, or drop `lastUpdated`.

## NIT

- N1 `.github/workflows/docs.yml:128`: `--branch=${{ github.head_ref || github.ref_name }}` is interpolated into the wrangler-action `command`. This is **not exploitable** today: wrangler-action runs it through `@actions/exec` (tokenised, no shell), git refnames cannot contain whitespace, and only same-repo branches get secrets. It is still the pattern that becomes injectable if someone later moves it into a `run:` step. Consider a comment to that effect, or computing the branch in a `run:` step via `env:` and passing it through `$GITHUB_OUTPUT`.
- N2 `.github/workflows/docs.yml:101`: the deploy job's `setup-bun` has no `bun-version-file`, so it gets an unpinned latest bun. Wrangler is also fetched twice: `bunx wrangler@…` at :111, then npm install inside wrangler-action. It works, but it is inconsistent with the pinned toolchain.
- N3 `ubuntu/package.json:11` and `AGENTS.md:48`: `format:check` runs `nx format:check` without `--all`, so it checks only changed files. CI runs `--all` (`ci.yml` "Check formatting"), so a local pass can still fail in CI. The local behaviour is unchanged from the old `npx nx format:check`. Consider `--all` in the script.
- N4 `website/scripts/render-toolchains.ts:197-203`: `code()` does not flatten newlines, but `escapeInline` does. A catalog `value` containing `\n` would break a table row. The catalog is controlled, so this is hardening only; `.replace(/\r?\n/g, ' ')` would cover it.
- N5 `.github/workflows/docs.yml:4-18`: the path filters omit `ubuntu/libs/core/**`, `ubuntu/tsconfig.base.json` and `ubuntu/package.json`. The generator executes all of these when it runs `main.ts` from source, so a breaking change there surfaces only on the next docs-triggering push. That risk is low because CI covers the CLI itself.
- N6 `website/public/favicon.svg`: has raw hex colours outside `theme.css`. This is a static asset, so the "colours only as tokens" rule arguably does not apply, but the rule as written in AGENTS.md is absolute.
- N7 `website/src/content/docs/ubuntu/troubleshooting.mdx:112` and `usage.mdx:120`: `sudo npx …` often fails with "npx: command not found" when Node comes from nvm, because sudo's `secure_path` drops it. A one-line hint (`sudo "$(command -v npx)" …` or `sudo -E env PATH="$PATH" npx …`) would help.
- N8 (pre-existing, not introduced here) `AGENTS.md` ("The publishable package is … (`main.js`, `package.json`, `README.md`)") and `ubuntu/README.md` both omit `LICENSE`, which is in the tarball.
